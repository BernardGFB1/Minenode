# MineNode Bedrock router extension

Geyser Standalone extension used by `backend/app/bedrock.py`.

It reads `routes.properties` from its Geyser data folder
(`extensions/minenode-router/routes.properties`), chooses the MineNode server from the hostname the
Bedrock player typed, and sets that server's online/offline authentication mode on each
`SessionLoginEvent`. Unknown or disabled hosts are rejected with a friendly message.

The extension is compiled ahead of time so the Docker image does not need a JDK at runtime. The
committed `MineNodeRouter.jar` must be rebuilt whenever the Java sources change.

## Build (Windows)

```powershell
./build.ps1 -GeyserJar C:\path\to\geyser-standalone.jar -Test
```

## Build (Linux/macOS)

```sh
./build.sh /path/to/geyser-standalone.jar --test
```

Use the same Geyser release that ships in production. The extension requests Geyser API `2.9.2`;
current standalone builds are backwards compatible.

## Route file

Generated by `backend/app/bedrock.py`:

```properties
denied-message=Ten adres nie jest dostępny przez Bedrock Edition.
route.0=survival.example.com|abc123|online|127.0.0.1|25565
route.1=creative.example.com|def456|offline|127.0.0.1|25565
```

`host|serverId|online|address|port`. The file is re-read when its modification time or size
changes, so server toggles do not require a Geyser restart.
